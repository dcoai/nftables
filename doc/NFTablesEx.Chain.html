    NFTablesEx.Chain (NFTablesEx v0.4.0)

    View Source

    High-level chain operations.

    Chains are containers for rules within a table. They can be either base chains (hooked directly into the kernel's netfilter framework) or regular chains (used for organizing rules and as jump targets).

    Chain Types

    Base Chains

    Base chains are directly hooked into netfilter and process packets at specific points in the network stack:

    • INPUT - Packets destined for local processes
    • FORWARD - Packets routed through the system
    • OUTPUT - Packets generated by local processes
    • PREROUTING - Packets as they arrive (before routing)
    • POSTROUTING - Packets as they leave (after routing)

    Regular Chains

    Regular chains are not hooked into netfilter. They organize rules and serve as jump targets from other rules.

    Hook Points and Chain Types

    Different hook points support different chain types:

    HookFilterNATRoute
    prerouting✓✓-
    input✓✓-
    forward✓--
    output✓✓✓
    postrouting✓✓-

    Priority

    When multiple chains hook the same point, priority determines evaluation order. Lower numbers are evaluated first. Common priorities:

    • -300 - Connection tracking
    • -200 - Mangle (packet modification)
    • -100 - DNAT
    • 0 - Filter (default)
    • 100 - Security
    • 200 - NAT
    • 300 - Mangle

    Quick Example

    {:ok, pid} = NFTablesEx.start_link()

# Create a base chain for filtering input packets
:ok = NFTablesEx.Chain.add(pid, %{
  table: "filter",
  name: "INPUT",
  family: :inet,
  type: :filter,
  hook: :input,
  priority: 0,
  policy: :accept  # Default action if no rules match
})

# Create a regular chain for custom rules
:ok = NFTablesEx.Chain.add(pid, %{
  table: "filter",
  name: "my_custom_rules",
  family: :inet
})

    Complete Firewall Setup

    # 1. Create table
:ok = NFTablesEx.Table.add(pid, %{name: "filter", family: :inet})

# 2. Create INPUT chain
:ok = NFTablesEx.Chain.add(pid, %{
  table: "filter",
  name: "INPUT",
  family: :inet,
  type: :filter,
  hook: :input,
  priority: 0,
  policy: :accept
})

# 3. Add rules
:ok = NFTablesEx.Rule.block_ip(pid, "filter", "INPUT", "192.168.1.100")

    Querying Chains

    To list existing chains, use NFTablesEx.Query.list_chains/2:

    {:ok, chains} = NFTablesEx.Query.fetch_chains(pid, family: :inet)

    Integration with nft Command

    Chains created with NFTex can be managed with the nft command:

    # Create with NFTex
NFTablesEx.Chain.add(pid, %{
  table: "filter",
  name: "INPUT",
  family: :inet,
  type: :filter,
  hook: :input,
  priority: 0,
  policy: :accept
})

# View with nft
$ nft list chain filter INPUT

# Delete with nft
$ nft delete chain filter INPUT

    add(pid, spec)

    @spec add(pid(), chain_spec()) :: :ok | {:error, term()}

    Add a chain.

    Base Chain Parameters

    • table - Table name (required)
    • name - Chain name (required)
    • family - Protocol family (required)
    • type - Chain type: :filter, :nat, or :route (required for base chains)
    • hook - Hook point (required for base chains)
    • priority - Chain priority (required for base chains)
    • policy - Default policy: :accept or :drop (required for base chains)

    Regular Chain Parameters

    • table - Table name (required)
    • name - Chain name (required)
    • family - Protocol family (required)

    Example

    # Base chain
NFTablesEx.Chain.add(pid, %{
  table: "filter",
  name: "input",
  family: :inet,
  type: :filter,
  hook: :input,
  priority: 0,
  policy: :accept
})

# Regular chain
NFTablesEx.Chain.add(pid, %{
  table: "filter",
  name: "my_rules",
  family: :inet
})

    build_add(spec)

    @spec build_add(chain_spec()) :: map()

    Build a command map to add a chain (without executing).

    Returns a map that would be sent to add a chain. Useful for batching, remote execution, or inspection.

    Parameters

    • spec - Chain specification map (same as add/2)

    Returns

    Map containing the chain add command

    Examples

    # Build base chain command
cmd = NFTablesEx.Chain.build_add(%{
  table: "filter",
  name: "input",
  family: :inet,
  type: :filter,
  hook: :input,
  priority: 0,
  policy: :accept
})
#=> %{"nftables" => [%{"add" => %{"chain" => ...}}]}

# Build regular chain command
cmd = NFTablesEx.Chain.build_add(%{
  table: "filter",
  name: "my_rules",
  family: :inet
})

# Use in batch
batch =
  Batch.new()
  |> Batch.add(Chain.build_add(%{...}))
  |> Batch.add(Chain.build_add(%{...}))

# Execute later
NFTablesEx.Executor.execute(cmd)

    set_policy(pid, table, name, family, policy)

    @spec set_policy(pid(), String.t(), String.t(), family(), policy()) ::
  :ok | {:error, term()}

    Set the default policy for a base chain.

    Note: This requires recreating the chain with the new policy. In nftables, policy is set at chain creation time.

    Parameters

    • pid - NFTex process pid
    • table - Table name
    • name - Chain name
    • family - Protocol family
    • policy - Policy (:accept or :drop)

    Note: Only base chains (chains with hooks) can have policies.

    Example

    :ok = NFTablesEx.Chain.set_policy(pid, "filter", "INPUT", :inet, :drop)
